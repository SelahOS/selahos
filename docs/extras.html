Extras & Fixes Worksheet

Creator apps that don't ship in the base install, and the exact commands for real issues found and root-caused across the project — nothing here is speculative.

Creator Apps

Ardour, Blender, GIMP, and OBS ship in the live ISO for the boot environment, but are deliberately left out of the base install — selah-setup uses a separate, lean package manifest. They're meant to come from Flathub instead:

flatpak install flathub org.ardour.Ardour org.blender.Blender org.gimp.GIMP com.obsproject.Studio

No GUI software center by default

The flathub remote is pre-configured, but Discover (the GUI app store) isn't installed by default:

sudo pacman -S discover

Wine / SelahBridge

Wine/SelahBridge missing after "Installation finished"

A known silent-failure mode: pacstrap can time out on wine-staging/wine-gecko and the installer doesn't hard-fail — it just reports no errors. Always verify directly:

pacman -Q wine-staging || sudo pacman -S wine-staging winetricks wine-mono wine-gecko python-pyqt6 python-mido python-rtmidi

"wine client error: version mismatch" on launch

A stale wineserver survives a Wine package upgrade and rejects every new launch against that prefix:

WINEPREFIX=~/.wine wineserver -k

Sign-in/activation opens real Firefox, never returns to the app

The correct hook is a per-prefix registry key, not a $BROWSER env var (confirmed not read by Wine at all). This is now baked into new installs' defaults — for an existing prefix, apply it directly:

WINEPREFIX=~/.wine wine reg add "HKCU\Software\Wine\WineBrowser" /v Browsers /d selahauth /f

Verify SelahBridge works end-to-end

Runs a real throwaway-prefix test: Wine init, file write, registry write, and the Windows audio API.

selah-bridgepro-selftest

An app's UI is a black or white screen on launch

Known limit: apps using WebView2/CEF/Electron for their UI need Direct2D 1.3, which Wine/DXVK/VKD3D don't implement yet — no current workaround. Check first: 
strings /path/to/app.exe | grep -i -E 'CoreWebView2|EdgeWebView'

System Health Tools

General health check after any install or update

sudo selah-postflight-check

Repair a broken install (bootloader, partitions, etc.)

sudo selah-doctor

Or, from a SelahOS USB booted on the broken machine — selah-repair can heal an installed system it's not currently running from.

Reapply the correct hardware profile

After moving a drive to different hardware:

sudo selah-seedcore-reapply

Known Hardware Issues

Wi-Fi association hangs on some Apple Broadcom cards, and internal speaker silence on some Cirrus-codec Macs, are both real open issues with workarounds and diagnostic scripts — tracked in full detail, kept current, on the dedicated page rather than duplicated here:

→ Beta 2.0.1 Known Issues & Workarounds

Writing the ISO / UEFI: always use dd, not Ventoy (see Live Boot). UEFI is required — legacy BIOS boot isn't supported — and Secure Boot must be disabled in firmware, since SelahOS doesn't ship signed bootloader keys yet.
